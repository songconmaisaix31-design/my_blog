今天，终究还是离职了。

说「终究」，是因为这件事我纠结快大半个月了。

真正让我下定决心的，是上游 Ali 把我的数据源掐断了。数据一没，好多正在迭代的东西直接就卡壳。更闹心的是，我做出来的所有东西全都留在公司：系统、流程、数据、业务场景，没有一样真正属于我。

代码是不是我写的，其实都还好。

最难受的是，我投入那么多时间、精力熬出来的成果，一旦离开这家公司，就很难再继续往下做。这种完全掌控不了自己作品的感觉，真的挺糟。

所以刚离职那会，我其实挺爽的。

终于不用围着一个已经废掉的数据源死磕，也不用在有限权限里费劲证明：AI 到底能给业务带来什么价值。

但开心劲一过，现实问题就来了。

很实在：没工资进账了。

好在我现在住家里，手里的存款按最低开销算，大概还能撑一年，不至于为了糊口随便找一份完全不想干的工作。

不过一年听着挺久，也不能就这么混日子耗过去。

我给自己定了个 90 天周期。

这三个月主要干几件事：打比赛、做项目、混圈子、练表达、投简历，同时补技术短板。

看着事情一大堆，其实逻辑很顺：靠比赛逼自己快速把项目做出来，拿项目攒作品集和实战经验，再靠这些作品去找下一份机会。

那我想找什么样的工作？

现在 Agent 特别火，我也想尽量往这个方向靠。我的感觉是，以后对开发者的要求，会越来越偏向综合能力。

当然这里说的「全能」，不是让一个人前端后端算法嵌入式一把抓，顺便还得修公司饮水机。

而是现在 AI 写代码越来越厉害，把明确需求翻译成代码这件事，会越来越不值钱。

以前开发者很大一部分价值，就是亲手敲出代码。以后代码还是得懂，但拉开人和人差距的，更多是这些事：面对模糊不清的问题能不能理明白；能不能设计靠谱的架构；把数据、模型、工具、权限、业务流程串到一起；搞定系统各种莫名其妙的 bug 和脏活；把只能演示的 Demo，真正落地到真实场景。

所以我想做的，不是传统意义上的全栈。

我更感兴趣的是 AI 应用、Agent、全栈系统，还有软硬件结合。

AI 只待在聊天框里，当然也有用。但想要真正落地干活，就得能感知现实，做判断，再通过软件或者硬件去执行。

从摄像头、传感器、手机、各种业务系统拿信息，交给模型思考决策，再去操控设备、跑通工作流。这套「感知—判断—执行—反馈」的闭环，我觉得是之后非常重要的方向。

说实话我离这个目标还差很远。

远就远吧，先朝着那边走就完事。

## 黑客松，我的高压训练场

上周参加了一场小型黑客松。拿奖固然好，但对我来说更大的收获是：确认自己可以快速上手陌生领域，还能带走一堆能用的经验。

有三点实打实的感悟。

**第一，多 Agent 协同开发。**

这慢慢变成我很重要的一套干活思路。

很多人做多 Agent，就是开好几个 AI 窗口同时改代码。结果就很搞笑，每个 Agent 都把自己当项目老大，抢着改同一个文件，活没干完，代码先互相打架。

我现在更喜欢的做法：**轨道隔离，互不冲突**。按文件目录划分各自地盘，而不是简单按功能分。每个 Agent 守好自己的分支，只改自己的文件；提前说好接口；做完一块就提交；最后专门留一个分支统一合并。

说白了，别把 Agent 单纯当写代码工具，要把它们当成一整个需要管理的开发小组。

以前自己写项目，我第一反应是这个功能怎么实现。现在我会先想：任务怎么拆分，才能让多个 Agent 一起干活，还不互相捣乱。

这不只是写提示词的小技巧，更像是一套新的做项目方式。

**第二，区块链、加密和智能合约。**

之前我对这块了解很浅，这次才算摸了个门。

私钥、签名、链上状态、智能合约、交易不可撤回，跟普通 Web 应用完全不是一套逻辑。

我也没打算直接转行做 Web3，更不想一头扎进密码学里面。但这次让我想通一件事：评判一套系统，不只是看它能不能跑起来。

它到底可不可信？权限归谁？操作能不能撤销？谁能代表用户做事情？

以后这些问题，一定会跟 Agent 撞在一起。如果 Agent 不只是帮你写写东西，还能帮你调工具、发起请求、管资产甚至付钱，那身份、授权、权限管控这些东西就特别关键。

虽然只是浅尝辄止，但也算打开新思路。

**第三，快速吃透 App 公开、半公开接口。**

这点刚好踩中我上份工作吃过的亏。当初项目因为上游断数据源直接崩盘，我深深体会到：AI 再聪明，拿不到数据，也是空转。

这次比赛我练了怎么快速看懂 App 数据流，从公开、半公开接口拿项目需要的数据。打短周期比赛的时候这个能力特别吃香。

很多时候项目不行不是模型不行，是没有真实数据。别人还在手动造测试数据，你要是能快速找到靠谱数据源，Demo 完整度直接拉开一大截。

当然，能访问不等于随便乱用。隐私、权限、访问频率、平台规则都得守好。厉害不是什么都能扒，而是知道哪些数据可以稳妥、合法拿来用。

## 为啥我疯狂报黑客松

刚打完迷你黑客松，明天又要去「纯爱战神黑客松」。北京这边能看到的黑客松，我基本都报名了。

看着像到处打卡刷经历，但我真不只是奔着拿奖。

想借这个圈子认识些同频的人，看看别人怎么做项目，顺便逼自己多开口表达。

我本身人多的时候不太敢说话。也跟家里有点关系，我姐总觉得我学开发才不到一年，就是半吊子，看不懂我做什么，也不相信我能搞出东西。

听多了确实会不爽。

但后来想明白了：「我学习时间短」是事实，「所以我不行」只是她的看法。

我确实还算新手，很多基础要补。但新手不等于没能力，学得晚不代表成长慢。况且她既不是行业面试官，也不是项目用户，她可以不理解，但我没必要把她的评价当成人生判决书。

我也不想天天在家跟她科普什么是 Agent、多 Agent、软硬件融合。在家里做没有评委的技术辩论，没啥意义。不如跑到真实的赛场，拿项目接受外人的反馈。

所以参加黑客松，也是逼自己练几件事：主动和陌生人搭话；完整讲清楚自己的项目；把还不成熟的想法当众说出来；接受别人的质疑；短时间跟一群人协作做完一件事。

能拿奖最好。拿不到也没关系，至少带走一个还能继续改的 Demo，几个聊得来的朋友，还有下次直接能用的实战经验。

## 接下来，不急着证明给谁看

离职之后最容易踩的坑，不是没收入，而是太想证明自己离职这件事做得有多对。

急着搞个大项目，急着拿奖，急着找到高薪工作，急着堵住所有不看好你的人的嘴。这种情绪短期很有干劲，但很容易把自己绷太紧。

我不想之后每打一场比赛，都是为了向谁证明什么。

我想建立属于自己的评判标准：今天有没有产出一点东西？表达是不是比之前好一点？有没有认识愿意踏实做事的人？比赛学到的东西有没有沉淀下来？离合适的机会是不是更近一步？

我最大的优势，不是现在有多强，而是我相信自己可以快速成长。

上一场比赛，我攒下了一套方法。下一场，直接带着这套东西继续上。只要每一次起步，都比上一次高一点点，那就不是无效打卡，而是在搭建真正属于自己的能力库。

公司的代码、数据、系统带不走。但怎么拆解问题、架构思路、踩过的坑、解决问题的思路，还有对真实业务的理解，全都是刻在自己身上的。

离职之后现金流确实断了。

但换个角度，我终于可以完完整整做一些真正属于我自己的东西。

现在我依旧是半吊子。

那又怎样，谁不是从半吊子，一点点打磨出来的呢。
